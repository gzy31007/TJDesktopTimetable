## 实现落点

- [BoardContentLayout.cs](../dotnet/Tjt.Widget/BoardContentLayout.cs)：Windows 显式启用内容预算，按实际三行文字高度分配非等高节次，跨节需求只约束覆盖行总高。中间空节次保留，空教室仍占中间文字行。固定区、画布及客户区不可绘制留白全部进入 RequiredHeight；高度不足不继续缩字。共享默认调用保留旧行为，Linux 未启用新路径。
- [BoardRenderer.cs](../dotnet/Tjt.App/Rendering/BoardRenderer.cs) 与 [MainWindow.xaml.cs](../dotnet/Tjt.App/MainWindow.xaml.cs)：WinUI TextBlock 量测与实际渲染共用样式、XamlRoot，禁用布局舍入；在内容根尺寸更新后重算。滚动器使用真实 Auto 范围，不以 Disabled 把 extent 压小来隐藏裁剪。
- [BoardScrollIdentity.cs](../dotnet/Tjt.Widget/BoardScrollIdentity.cs)：比较实际内容与范围，不将内部 id、导入元数据、主题或时间强调算作新内容。重绘、相同课表重载保持偏移，内容或范围变化归顶；连续重绘尚未 Loaded 时也保留待恢复偏移。
- [WindowPlacement.cs](../dotnet/Tjt.Widget/WindowPlacement.cs)、[ResizePolicy.cs](../dotnet/Tjt.Widget/ResizePolicy.cs) 与 Windows 外壳：外框基本下限仍为 320×240 DIP。外框超工作区才适配，保存适配结果；保存物理外框和 DPI 比例，避免整数 DIP 往返导致非整数 DPI 重启尺寸增长。旧 Bounds 继续可读，不保存滚动模式。

原型数值 530、525.38、104 没有变成生产统一窗口高度。27 DIP 基础行高、课程名字号 9.5–12、时间 11 已接入并通过本机实际文字几何检查；其他 DPI 的可读性仍待人工核对。

## 本机真实 Windows 验证

首组环境：实际屏幕 2560×1600 物理像素，工作区 2560×1528，GetDpiForWindow=144，比例 150%。使用[纯虚构验收课表](../dotnet/fixtures/board-content-synthetic.json)，固定 `--today 2026-09-21 --now 07:00`。首组未修改系统显示配置，桌面层与背景材质关闭；后续由用户切换系统缩放、分辨率并恢复，人工组另启用了桌面层与材质。

复用 [ImportSessionCheck.cs](../dotnet/Tjt.App/Diagnostics/ImportSessionCheck.cs) 的隔离会话入口；新增 board-* 动作用真实挂载的 WinUI 树、ScrollViewer extent/viewport/offset 及窗口 API 记录结果，不是浏览器模拟。阈值操作从实际内容反推，且最终与实际三行高度、画布和视口独立核对。

### 高度与滚动

实际固定区消耗 64.6667 DIP，其中顶栏 34、摘要 30，XAML 岛外客户区另占 1 物理像素。画布已包含星期头与上下留白，密集表画布高 452.5508 DIP，客户区总需求约 517.21745 DIP。

| 目标 | 实际客户区 DIP | 实际客户区物理像素 | 实际纵向范围 DIP |
| --- | ---: | ---: | ---: |
| 略低于需求 | 516.6667 | 775 | 0.55078 |
| 达到需求，向上取整至可实现的整像素 | 517.3333 | 776 | 0 |
| 高于需求 | 518.6667 | 778 | 0 |

不能把数学上的小数 DIP 高度强行设置为半个物理像素。达到需求一行按物理像素向上取整，不使用容差掩盖真实范围。

通过的真实运行断言：

- 低于门槛可滚到 ScrollableHeight；达到和高于门槛画布含末行完整落入视口，真实范围为零。
- 所有已挂载课程均有三行；空教室文字行实际高度大于零；每块三行实际高度之和不超过其内高。
- 在 300 DIP 高度滚到 80 DIP 后，连续两次无 await 重绘、主题变更、重新载入与相同课表重新导入均保持 80；周次或周末范围改变归零。
- 在同一 510 DIP 窗口，切换 current/all 可退出/进入滚动，物理外框不变；更短的跨节课表导入后首尾裁剪、退出滚动，外框仍不变。

19 条运行时断言通过，重复色块的逐块三行内高断言计入条数。观测快照与日志在[本机高度与滚动证据目录](</mnt/c/tjt-tools/issue21-board-20261018-2126/>)，不随源码发布。

### 保存恢复与工作区

独立隔离目录中，手工设置前均等待诊断应用退出。

- 1001×401 物理像素短外框连续两次重启仍是 1001×401，不按课表撑高，真实滚动范围非零。
- 保存的 5000×3000 外框恢复时缩小并完整移入实际工作区，结果为 2560×1528；下一次重启仍是 2560×1528。
- 移除新增物理尺寸/DPI 字段的旧格式 640×250 DIP 外框恢复为 960×375 物理像素，仍可临时滚动，不按内容撑高。

证据在[本机保存恢复目录](</mnt/c/tjt-tools/issue21-placement-20261018-2130/>)。这验证了启动时适配真实工作区和持久化，**不等同于热插拔屏幕、实际缩小系统工作区或混合 DPI 跨屏已验收**。

分别以显式 `--size 1080x530` 和 `1080x300` 捕获了虚构课表的拥有窗口，尺寸为 1620×795、1620×450 物理像素。PrintWindow 的透明背景不适合作为颜色/材质可读性证明，未据此声称背景材质通过。图片仅保存在[本机捕获目录](</mnt/c/tjt-tools/issue21-capture-20261018/>)。

### 补验：真实系统缩放、人工交互与工作区变化

150% 配对诊断人工窗口启用桌面层与 Mica。用户确认拖动、缩短后鼠标滚到末行、拉高后退出滚动、文字/悬停/背景均正常；日志记录了实际拖缩和 Mica/MicaAlt/AcrylicThin 切换。此组结束采集因用户关闭或重建设置窗口后访问旧控件发生 COMException，不算自动快照通过。已修复人工步骤只观测存活的课表树，下一组收尾验证成功。[人工交互日志](</mnt/c/tjt-tools/issue21-manual-isolated-20261018-2238/>)。
