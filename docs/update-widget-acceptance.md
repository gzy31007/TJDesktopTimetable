# Windows 更新入口与周期检查验收

关联：[#26](https://github.com/gzy31007/TJDesktopTimetable/issues/26)。2026-10-20，源码基线 `c296b41`，修复提交 `9e90198`。本记录不是发布或安装验证。

## 修复与复现

旧版本的 `SettingsHost.HasUpdate` 在打开窗口时取 bool 快照，描述文字却读取实时结果；刷新页面不重建 host，因此会出现“文字说有新版、按钮仍不出现”。实施前复跑生产方法隔离探针，两轮均复现该差分；探针使用真实网络及版本方法，但 UI/dispatcher/通知为替身，不作为 Windows 实机证据。

现在将下载入口迁移到挂件顶部：只在当前结论 `HasUpdate` 时构建“下载新版”，异步结果变化和跳过会立即重绘。关于页保留手动检查和实时条件下的跳过，不再提供下载按钮。通知点击仍打开关于页，正文和关于页说明下载入口在挂件顶部。

Windows 外壳启动约 12 秒后检查，随后每轮完成后间隔 6 小时重查；每轮读取当前开关。手动检查与自动检查共用并发门禁，关闭自动检查不禁用手动检查，退出取消等待与网络请求。分发时再读取跳过版本，避免请求期间的跳过被旧响应覆盖。没有新增内置下载器、自动安装或 Linux 更新系统。

## 隔离 Windows 实际控件

两次均运行出货 WinUI 应用与真实 XAML，loopback HTTP 提供合成正式版本；没有注入 UpdateAvailable 替身。沿用配对 `--session-check` / `--diagnostic-dir`，关闭桌面层、托盘、自启及自动更新；由实际关于页按钮触发手动检查和跳过，由真实挂件按钮的 AutomationPeer Invoke 触发下载动作。

| 环境 | 控件流程 | 退出与数据安全 |
| --- | --- | --- |
| 深色，客户区 320×260 DIP | 11 步通过，7 次 API 请求 | 退出 0；真实 settings/timetable/credentials 三文件哈希不变 |
| 浅色，客户区 1280×740 DIP | 同一流程通过 | 退出 0；同样三文件哈希不变 |

同一设置窗口不重开，流程为：未检查 → 合成 v99（安装器及 zip）→ 点击下载 → 跳过 → 再查 v99 仍跳过 → 合成 v100（仅 zip）再次提示并点击 → 合成低版本清除入口 → HTTP 503 保留当前结论 → 合成 v101 再提示 → HTTP 503 保留新版入口。

每步断言关于页有可再次使用的检查按钮、没有下载按钮；跳过按钮只随当前 `HasUpdate` 出现。所有有新版步骤均观察到已加载、启用、祖先可见的“下载新版”。最窄客户区按钮位置 x=179.039 DIP、宽 64.961 DIP、高 26 DIP；右动作区终点 x=312 DIP，小于客户区 320 DIP；标题实际宽 32.227 DIP，使用既有省略规则。没有把模型计算或零尺寸未加载控件当作几何证据。

- 安装器：`https://gh-proxy.org/https://github.com/gzy31007/TJDesktopTimetable/releases/download/v99.0.0/package-setup.exe`

本地辅助脚本 `.tools/update-session-check.ps1` 和观测 `.artifacts/issue26-implement/evidence/` 不入提交；摘要、完整 session、计划、合成响应、API 计数与应用日志已留在工作区。Windows 原始目录为 `C:\tjt-tools\issue26-ui-20261020-narrow-final` 和 `C:\tjt-tools\issue26-ui-20261020-wide`。首次窄窗口的控件断言通过，但 HttpListener 清理卡住并报 PSRemotingTransportException，未将该次计为完整验收；修正本地脚本的显式停止路由后，窄窗口重跑退出 0，数据哈希检查完成。此修正不涉及产品代码。
