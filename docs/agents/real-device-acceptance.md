# 真机验收：范围与成本

安排或扩展真机验收前读取。以下是取舍原则，不新增固定审批、全量矩阵或额外报表。

## 按风险确定范围

- 数据与配置安全、已确认的核心功能缺陷是阻断项。复用已有隔离入口，开始人工操作前确认实际写入目录；安全底线沿用根目录 [AGENTS.md](../../AGENTS.md#验证与提交)。
- 核心行为先用已有单测、目标平台构建和代表性真机检查覆盖。根据改动影响选择其他环境，不默认做 DPI、屏幕、材质等维度的全排列；与改动无关且已有有效证据的检查不重复执行。
- 已确认规格中的必验项仍然有效。建议延期时，说明风险并取得用户确认；缺设备就记录未验，不用模拟或编译结果冒充通过，也不自行降低结案标准。

## 给验证设预算和停止条件

- 开始前简述要排除的风险、验证范围，以及代理执行和用户操作的粗略耗时；可以并入现有任务说明，不另建计划或报告。
- 计划内检查通过且无已知阻断问题时停止扩展并交接。新增检查须对应一个尚未覆盖的具体风险；“还能再测”本身不是理由。
- 连续两轮主要在修诊断工具而非产品缺陷，或预计投入超出预算时，暂停扩展，汇总已获证据和剩余风险，合并提出取舍建议。优先复用、缩小探针；超预算不是把未通过写成通过的理由。

## 节约用户参与成本

- 先完成可自行执行的准备与自检，再请求人工操作。一次性交代动作、预期结果、预计耗时和系统状态恢复方法；同一环境尽量合批，避免逐项打断和重复索取证据。
- 用户只承担机器无法替代的判断或操作。已有观测可回答的问题由代理处理；环境不可得时明确交接剩余项，是否等待这些证据由已确认的交付范围决定。
