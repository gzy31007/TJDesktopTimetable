# TJDesktopTimetable v1.3.1

**Linux 壳集中修复**（对应 [Issue #2](https://github.com/gzy31007/TJDesktopTimetable/issues/2) 的六项）：布局与 Windows 线对齐、X11 贴桌面层两处真 bug、导入诊断链路打通、凭据落盘收紧、外壳健壮性。Windows 侧无功能变化，只是跟着版本号一起发。

感谢 [@Little-Red-Stone](https://github.com/Little-Red-Stone) 的 [PR #3](https://github.com/gzy31007/TJDesktopTimetable/pull/3)。

## 下载

- `TJDesktopTimetable-v1.3.1-win-x64.zip` · Windows（自包含：**不需要**预装 .NET 或 Windows App Runtime）
  → 解压到任意**本地磁盘**目录 → 双击 `Tjt.App.exe`
- `TJDesktopTimetable-v1.3.1-linux-x64.tar.gz` · Linux（自包含单文件：**不需要**预装 .NET）
  → `tar -xzf ...` → 运行解压目录里的 `Tjt.Linux`

## 修复（Linux 壳）

- **紧凑布局与 Windows 同口径**：`TrimEmptySlots = true` 之前漏传，两端行数 / 行高 / 纵向滚动判定会分叉
  （黄金 fixture 的最大节次恰好是 11，所以一直没暴露；换成内置样例就能看出 Linux 画 1..11 节、Windows 只画 1..6 节）。
- **X11 事件掩码写错**：`_NET_WM_STATE` 客户消息用的是 `SubstructureNotify | ResizeRedirect`，
  正确的是 `SubstructureNotify | SubstructureRedirect`（`1<<19 | 1<<20`）—— 只订阅后者的窗口管理器**收不到**这条消息，
  keep-below 会静默失效。
- **失败不再"假报成功"**：`XSendEvent` 返回 0（无人订阅）时改记错误日志，而不是打出"贴桌面层 开启"。
- **导入诊断链路打通**：导入窗口现在渲染**适配器诊断**（`tongji.term.unknown` / `tongji.schedule.missing` 这类
  "导入看似成功、其实学期或节次解析不对"的唯一提示）并逐条落日志；`--fetch-check` 也接上了完整的导入管线
  （带学期 id），**退出码从此代表"能解析成课表"**，不再只是"网络通 + 响应像课表"。
- **凭据落盘收紧**：`credentials.json` 写 0600、数据目录 0700（这份文件里是含 cookie 的整条请求，
  而 `~/.config` 默认 umask 下同机可读）。
- **外壳健壮性**：字体候选改为过 `fc-list` 验证（原来是一段死代码：`fc-match` 失败就落回多半不存在的
  `Microsoft YaHei`）并给 Avalonia 配上 CJK 回退链；`fc-match` / `gsettings` 改走**带超时的子进程**
  （原来阻塞式 `ReadToEnd`，helper 一挂住就拖死启动）；`Main` 与 `App` 加顶层异常兜底（GUI 无控制台时
  崩溃至少会留下 `[fatal]` 日志）。
- 顺带把"首次启动自动打开导入窗口"的触发条件对齐 Windows 口径（只认内置样例 / 黄金数据，
  `--fixture` 这类显式路径不再被导入窗口盖住），并新增 `--import-window` / `--no-import-window`。

## 变更（Linux 贴桌面层：DOCK → DESKTOP）

- 窗口类型从 `_NET_WM_WINDOW_TYPE_DOCK` 换成 **`_NET_WM_WINDOW_TYPE_DESKTOP`**，并在开启后跟一次
  `XRaiseWindow`。原因：KWin **5** 的 `layerForDock()` 会把 keep-below 的 dock 压到 Normal 层（恰好可用），
  但 KWin **6** 起 `belongsToLayer()` 对 dock 直接给 `AboveLayer`（keepBelow 分支走不到）—— **DOCK 一开就被置顶**
  （v6.7.5 实测）。
- 注意：v1.2.0 / v1.3.0 的 Linux 版用的正是 DOCK。如果你在 KWin 6 上遇到"挂件跑到所有窗口最上面"，
  这一版就是修复。若换成 DESKTOP 后**在你的桌面环境里**贴桌面层不生效（或不能拖动），
  请开 issue 附 `xprop -id <窗口id> _NET_WM_WINDOW_TYPE _NET_WM_STATE` 的输出。

## 质量

- 平台无关单测 **270** 项全绿（v1.3.0 是 269，新增一条钉住"紧凑布局分叉"的用例：
  用内置样例形状断言收窄到 6 行、不收窄退化为 11 行，以及随之变化的行高与纵向滚动判定）。
- Linux 外壳**清空 bin/obj 全量重建**：0 警告 0 错误（`TreatWarningsAsErrors=true`）。
- 真机实测（WSL，无 DISPLAY）：`--fetch-check` 打本地合成服务 → 探测行 + 3 条诊断 +
  `解析 tongji-student：14 门 / 19 条，学期 2026-2027学年第1学期`、退出码 0；抓取失败（端口无服务）退出码 1；
  `--import` → `adapter=tongji-student 14 门课程 / 19 条上课安排 applied=True`。

## 已知限制

- Linux 版的贴桌面层依赖 **X11 / XWayland**；`DESKTOP` 类型的实际操作（能否拖动 / 缩放、
  「显示桌面」后是否仍可见）目前**只在 KWin 上实测过**，其他窗口管理器请用 WM 自身的窗口规则兜底。
- 其余限制与 v1.3.0 相同：Linux 无托盘与独立设置窗口；Windows 版内置登录需 WebView2 运行时；
  研究生 `findSchoolTimetab2` 分支未真机实测；内置学期表只覆盖已知学期；周次过滤（只看单周 / 双周）尚未接 UI。
- 本版复审发现的 4 处小瑕疵已开 [Issue #4](https://github.com/gzy31007/TJDesktopTimetable/issues/4) 跟进
  （X11 返回值判据、子进程双超时、注释措辞、CLI 文档），不影响使用。
