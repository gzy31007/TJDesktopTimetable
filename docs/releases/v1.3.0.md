# TJDesktopTimetable v1.3.0

**新版本提示**（启动后自动查一次 GitHub 最新发布）+ 两项上一代能力回归（**开机自启**、紧凑相关的文案修正）。

## 下载

- `TJDesktopTimetable-v1.3.0-win-x64.zip` · Windows（自包含：**不需要**预装 .NET 或 Windows App Runtime）
  → 解压到任意**本地磁盘**目录 → 双击 `Tjt.App.exe`
- `TJDesktopTimetable-v1.3.0-linux-x64.tar.gz` · Linux（自包含单文件：**不需要**预装 .NET）
  → `tar -xzf ...` → 运行解压目录里的 `Tjt.Linux`

## 新增

**新版本提示（Windows）**

- 启动后**后台线程延迟 12 秒**查一次 GitHub 上的最新正式发布（`/releases/latest`，只读版本号）。
- 有新版本时**两个入口同时提示**：托盘菜单多出一项「发现新版本 vX」（点开直接下载）+
  托盘提示带版本号；设置「关于」页那一行也会写明，并给出「下载」「跳过此版本」两个按钮。
- **跳过此版本**：只压住你跳过的那一个版本，之后出现更高的版本照样提示。
- **可关**：设置「常规」页一个开关（默认开）。关掉之后应用完全不联网。
- 失败一律**静默**（没网 / 被限流 / 公司代理拦了都只在日志里记一行），不会弹错误框、不影响启动。
- 只认**正式 Release**：预发布与草稿不提示；版本比较只看前三段（`v1.3.0` ↔ 本机 `1.3.0.0`）。

**开机自启（Windows）**

- 设置「常规」页勾一下，登录 Windows 后自动把挂件放回桌面。
- 写的是**当前用户**的启动项（`HKCU\...\CurrentVersion\Run`，不需要管理员）；关掉时会把那一项**删干净**
  ——不是"设置里关了、开机照样起"。
- 启动时按设置对一次账（幂等）：换过安装目录、或用户手工清过启动项，下一次启动会自动纠正。

## 修复

- **导入诊断里那句「可在设置里手动填开学日期」是空头承诺**：设置页从来没有这一项（旧 Electron 线也没有）。
  现在改成真实可行的出路 —— 若能一并导入校历响应，即可从 `beginDay` 补上开学日期。

## 变更

- **README 的「离线」口径改为「离线优先」**：课表 / 账号 / 行为数据仍然只落在本机、不上传；
  唯一的联网行为是上面那次版本查询（只读版本号，不发送任何本机信息），且可以关掉。
- 文档修正：`AGENTS.md` 里"`wallpaper`（WorkerW）作为可选 / 回退模式保留"的说法与代码不符 ——
  该方案早已否掉（会被桌面图标压住、拖动坐标错乱、抢 Explorer 时序），现行只有桌面层 + 失败回退置底。

## 质量

- 平台无关单测 **269** 项全绿（v1.2.0 是 237；新增 25 项覆盖版本解析 / 比较 / 跳过 / 资产匹配，7 项覆盖开机自启的命令行约定）。
- 新增验收脚本：`.tools/verify-update-check.ps1`（本地合成 GitHub API 跑六例：有新版 / 已最新 / 响应非法 /
  网络失败 / 跳过 / 关于页构建）、`.tools/verify-autostart.ps1`（开 / 关 / 纠正错误启动项，跑完还原设置与注册表）。
- 真机实测：`--update-check` 打到真 GitHub API → 本机 `1.3.0` / 线上 `1.2.0` → `UpToDate`
  （版本解析与"只看前三段"的比较都正确）；开机自启三例全绿并把设置与注册表还原。

## 已知限制

- **更新检查需要能访问 GitHub**：墙内直连不通时需要系统代理（本项目不做镜像回退 —— 能下载到本软件的用户
  通常已经能访问 GitHub）。
- **新版本提示与开机自启只做 Windows**：Linux 壳（fork 线）不带这两项 —— 检查逻辑本身在平台无关的 `TjtCore` 里，
  将来要接只需补壳层。
- 其余限制与 v1.2.0 相同：Linux 版 X11 / XWayland only、无托盘与设置窗口；Windows 版内置登录需 WebView2 运行时；
  研究生 `findSchoolTimetab2` 分支未真机实测；内置学期表只覆盖已知学期；**周次过滤（只看单周 / 双周）尚未接 UI**。
